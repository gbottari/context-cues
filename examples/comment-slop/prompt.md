Comments are ${SHARE}% of the lines your last commit added. Comments say why the code is the way it is: a constraint, a decision, a trap. One line where one line will do. The code already says what it does, and the commit says what changed, so a comment repeats neither. Look at the comments in that commit: shorten any that run longer than they need, delete any that restate the code, keep the ones that say why, and amend it if anything changed, unless it is already pushed.
