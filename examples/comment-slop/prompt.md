The rules for comments: a comment says why the code is the way it is, such as a constraint, a decision or a trap. The code already says what it does, and the commit says what changed, so a comment repeats neither. One line where one line will do. A comment states the rule the code follows now, not the history of how it got there. Follow these rules even where this repository's own conventions differ.
